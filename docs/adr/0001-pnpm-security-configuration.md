# ADR-0001: pnpm セキュリティ設定の導入

- **ステータス**: 承認済み
- **決定日**: 2026-02-20
- **決定者**: 開発チーム

---

## コンテキスト

npm から pnpm への移行（`feat/npm-to-pnpm`）に伴い、パッケージ管理のセキュリティを強化する機会が生じた。

npm/pnpm のエコシステムでは、以下のような攻撃手法が実際に観測されている。

- **サプライチェーン攻撃**: 既存の人気パッケージに類似した名前の悪意あるパッケージを公開し、タイポミスを誘う（タイポスクワッティング）
- **パッケージハイジャック**: メンテナのアカウントを侵害し、既存パッケージに悪意あるコードを混入させた直後に被害が広がる
- **ポストインストールスクリプト**: `postinstall` スクリプトを通じた任意コード実行

これらの攻撃は、悪意あるバージョンが公開されてから短期間（数時間〜数日）でセキュリティ研究者や監査ツールに検出されることが多い。
**公開直後のパッケージをインストールしないことが有効な対策となる。**

---

## 決定

pnpm の設定ファイルおよびフック機構を活用し、以下の4つの対策を導入する。

### 1. `.npmrc` — 基本セキュリティ設定

| 設定 | 値 | 目的 |
|------|-----|------|
| `verify-store-integrity` | `true` | ストア内パッケージのチェックサム検証 |
| `strict-ssl` | `true` | HTTPS 通信の強制 |
| `prefer-frozen-lockfile` | `true` | lockfile の意図しない更新を防止 |
| `registry` | `https://registry.npmjs.org/` | 使用レジストリの明示（意図しないミラー利用の防止） |

### 2. `.pnpmfile.cjs` — パッケージ年齢チェックフック

`afterAllResolved` フックにより、`pnpm install` の依存解決後に以下を実施する。

- npm レジストリに問い合わせ、各パッケージの公開日時を取得
- **公開から 7 日未満のパッケージが含まれる場合はインストールを中止**しエラーを表示
- チェック結果は `.pnpm-age-cache.json` にキャッシュし、2回目以降の重複リクエストを排除
- ローカルディレクトリ依存・git 依存はチェック対象外
- 緊急時は `PNPM_SKIP_AGE_CHECK=1` 環境変数でスキップ可能（非推奨）

フックの実行タイミング:

```
pnpm install
  └─ 依存解決（resolution）
       └─ afterAllResolved フック ← ここで年齢チェック
            └─ パッケージ取得・インストール
```

### 3. `package.json` — セキュリティ監査スクリプト

```jsonc
"security:audit":     "pnpm audit --audit-level=moderate"  // CVE 確認
"security:audit:fix": "pnpm audit --fix"                   // 自動修正
```

### 4. `.gitignore` — キャッシュファイルの除外

`.pnpm-age-cache.json` はローカル環境固有の情報（チェック実施日時）を含むため、リポジトリから除外する。

## 検討した代替案

### 案A: Socket Security (socket.dev) の利用

Socket はパッケージの挙動解析・公開直後検出を提供する SaaS。
**不採用理由**: 外部サービスへの依存が増加し、プライベートリポジトリの情報が外部に送信される懸念があった。

### 案B: Dependabot / Renovate のみ

自動 PR によるバージョン管理ツール。
**不採用理由**: 既知の CVE 対応には有効だが、公開直後の悪意あるパッケージ（まだ CVE が存在しない）には無効。

### 案C: `ignore-scripts=true` の設定

postinstall スクリプトを完全に無効化する最もシンプルな対策。
**不採用理由**: `esbuild`・`vite` など、ネイティブバイナリのビルドに postinstall を必要とするパッケージが動作しなくなる。

## 影響・トレードオフ

### メリット

- 公開直後の悪意あるパッケージによるサプライチェーン攻撃を自動ブロックできる
- pnpm の標準フック機構を使うため、追加の npm パッケージ不要
- キャッシュにより、既存パッケージの再チェックコストはほぼゼロ

### デメリット・注意点

- **初回インストール時**: 全パッケージ分の npm レジストリへの HTTP リクエストが発生し、インストール時間が増加する
- **7日ルールの副作用**: 緊急のセキュリティパッチ（パッチバージョン）も公開から7日間はインストールできない。緊急時は `PNPM_SKIP_AGE_CHECK=1` でスキップする
- **プライベートパッケージ**: npm レジストリ以外のプライベートレジストリのパッケージは、レジストリ問い合わせが失敗した場合にチェックがスキップされる（フェイルオープン）
- **ネットワーク障害時**: レジストリへの接続が失敗した場合もチェックがスキップされる（フェイルオープン）
